# Gaming Hub — تسليم إصلاح صوت Android

التاريخ: 19 أكتوبر 2026. المستودع: `iroaa15-bot/GamingHub`.
الفرع المسموح: `fix/android-voice-root-cause` فقط.
نقطة البداية: `1586d38fa16dd0b3d4531abd03428a45ac6dbd70`.

**الحالة: تنفيذ متصل باللعبة وتحقيق برمجي محلي؛ جودة الصوت على هاتفين حقيقيين لم تُثبت بعد.**
لم يُنشأ APK أو AAB، ولم يُنشر السيرفر المعدل، ولم يُعدّل main أو أي مشروع آخر.

## المشكلات المعالجة

- كان مجلد الإضافة يحوي ملفي Kotlin فقط، بلا Gradle أو Manifest أو تسجيل في Godot أو AAR يستخدمه التصدير. أصبح مشروع Android Library كاملًا، مع Gradle Wrapper مثبت التحقق، وملفي AAR مبنيين فعليًا، وEditorExportPlugin مفعّل يضيفهما لتصدير Android.
- الواجهة لم تكن تستدعي تفعيل الصوت. أصبح زر اختياري داخل شاشة الأونلاين مرتبطًا بطلب إذن الميكروفون ثم موافقة السيرفر؛ الميكروفون لا يبدأ قبل موافقة الطرفين المؤكدة.
- اللاعب المنضم والمطابقة العشوائية لم يكونا يحتفظان بكود الغرفة من `started`. أصبح الكود يُحفظ ويُستخدم لربط الصوت والاستعادة.
- التسجيل والتشغيل منفصلان عن خيط Godot، وإدارة البدء والإيقاف على executor تسلسلي. الإشارات الحالة تُرسل عبر آلية Godot الأصلية إلى render thread؛ أزيلت مهام UI لكل إطار صوت.
- تفعيل `MODE_IN_COMMUNICATION` و`VOICE_COMMUNICATION` ومسار سماعة الهاتف، مع دعم API 24+ وحراسة مسار API 31+. السماعات ليست شرطًا. أزرار الصوت تتحكم بمستوى المكالمة أثناء الجلسة؛ لا نرفع مستوى النظام بالقوة.
- تفعيل AEC وNS وAGC عندما ينفذها الجهاز ويقبل تفعيلها، وإرفاقها بجلسة AudioRecord الصحيحة. أضيف تطبيع رقمي محافظ للكسب عند غياب AGC، مع سقف للكسب ومنع القص وعدم تضخيم الصمت.
- الجسر يسحب PCM من مخزن محدود بدل إشارات متراكمة. التشغيل يستخدم مخزن jitter محدودًا، وفحص تسلسل، وكتابة تتعامل مع النتائج الجزئية وأخطاء I/O، وتوقيت 20 ms، وصمتًا عند نقص البيانات.
- أضيف `protocol=2` و`epoch` و`seq` وحالة موافقة كاملة، ورفض الحزم القديمة أو المكررة أو الآتية من اللاعب نفسه. أخطاء الصوت لا تلغي حركة لعب معلقة.
- إرسال الصوت على السيرفر له outbox محدود وعمر أقصى للحزم ومهلة للمتلقي البطيء؛ لا يُعطل حلقة استقبال حركات اللاعب السليم. بقي مسار العملاء الأقدم متوافقًا؛ العميل الجديد يطلب البروتوكول 2.
- فقد الاتصال والمغادرة ونهاية المباراة والخلفية وفقد audio focus تُوقف الصوت وتمسح المخازن. استعادة المباراة تستخدم نفس الغرفة وتدوير token، ثم تتطلب تفعيلًا جديدًا للصوت. لا يعاد تشغيل الميكروفون خفية.
- الإضافة الموزعة تحمل بصمة مصدرها. `tools/verify_voice_aar.py` يرفض AAR قديمًا لا يطابق ملفات Kotlin وManifest وإعدادات البناء.
- جرى تحديث manifest حزمة المصدر ليشمل native وأدوات التحقق، مع استبعاد مخازن البناء وملفات الاستيراد التلقائية. صُححت اختبارات قديمة كانت تتوقع إلغاء حركات اللعب بسبب أي رسالة خطأ، واختبار صلاحيات كان يقرأ قسم preset بدل options.

اختبارات WebSocket تستخدم PCM مولدًا بمعدل 50 إطارًا/ثانية في الاتجاهين، 110 إطارات لكل طرف، مع heartbeat أثناء النقل. تختبر أيضًا الموافقة، الفصل، تدوير رمز الاستعادة، رفض epoch قديم، التكرار، والمخزن المحدود والمتلقي البطيء. اختبار Godot الكامل يمر عبر كود اللعبة الفعلي، ويستبدل حد Android/JNI فقط بمحاكي ينتج PCM ويفحص ما يستقبله.

هذه الاختبارات **ليست** تسجيلًا أو استماعًا من هاتف حقيقي. `adb devices -l` لم يجد أجهزة. لوحظ في تشغيل مبكر لاختبار الأركيد تحذير تحرير AudioStreamWAV الخاص بمؤثر `feedback_success.wav` عند الخروج؛ لا يمثل قياسًا لصوت المحادثة. آخر تشغيل لجميع فحوص Godot المذكورة اكتمل دون SCRIPT ERROR أو ERROR؛ السجلات موجودة في `docs/voice_validation`.

## أوامر إعادة التحقق

المتطلبات: JDK 17، Android SDK وفيه `platforms;android-36` وbuild-tools 35/36، Python مع `server/requirements.txt`، وGodot 4.5.1.

```bash
cd native/android-voice
./gradlew --no-daemon --max-workers=2 testDebugUnitTest lintDebug lintRelease installPlugin
cd ../..
python tools/verify_voice_aar.py
python release/source_manifest.py
python tests/run_checks.py
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/voice_runtime.gd
python tests/run_voice_room_runtime.py --godot godot
godot --headless --path . --script res://tests/godot_smoke.gd
godot --headless --path . --script res://tests/release_runtime.gd
godot --headless --path . --quit-after 60
```

بعد تعديل native يجب إعادة `installPlugin`؛ فبصمة المصدر ستمنع قبول AAR قديم. بعد تغيير مصدر أو وثائق الحزمة، أعد `python release/source_manifest.py --write` ثم تحقق منه. لا تشغل workflow بناء تطبيق أثناء هذه الفحوص.

## ما لم يُثبت وما يلزم على Android

1. تسجيل وتشغيل حقيقيان ونجاح تحميل singleton داخل التطبيق النهائي، ودمج صلاحيات Manifest النهائي ورفض/قبول/سحب إذن الميكروفون.
2. مكالمة بين هاتفين في مكانين منفصلين، بدون سماعات، بكلام متبادل ومتزامن لمدة 10–15 دقيقة. اختبار OPPO A31/Android 10 وهاتف Android حديث API 31+، وعند الحاجة Redmi 9C.
3. قياس وضوح الصوت ومستواه وقصه والصدى الفعلي والتأخير والتقطيع. قياس AEC في الكلام المتزامن، ومراجعة سطر `VOICE_CAPABILITIES` في debug لمعرفة ما فعله الجهاز فعلًا.
4. تغيير مستوى المكالمة، إدخال/إخراج سماعة اختيارية، مكالمة هاتف واردة، الخلفية/العودة، وسحب الإذن أثناء الجلسة؛ التحقق من توقف الميكروفون وعدم وجود جلسات أو audio focus متسربة.
5. شبكة Wi-Fi ثم بيانات الهاتف، وفقد الشبكة والعودة خلال نافذة الاستعادة، وتجربة زمن تأخير/فقد مرتفع؛ التأكد من سلامة المباراة والصوت بعد الموافقة الجديدة.

حدود مهمة: معالجة AEC وNS هنا تعتمد على تنفيذ Android/OEM؛ لا توجد مكتبة software AEC مستقلة تضمن إزالة الصدى في كل هاتف. PCM على WebSocket/TCP ما زال معرضًا لتأخير head-of-line على الشبكات السيئة؛ المخازن محدودة لكن ذلك لا يحوله إلى RTP/Opus أو WebRTC. لا تدّعِ زوال الصدى أو حل انخفاض الصوت على الأجهزة قبل الاختبار الحقيقي.

السيرفر العام لم يُحدَّث ضمن هذه المهمة. العميل الجديد يحتاج السيرفر المعدل الداعم للبروتوكول 2؛ يفضل نشر الفرع في بيئة اختبار منفصلة قبل أي دمج أو نشر عام. لا تغيّر main لمجرد استكمال التحقق.
