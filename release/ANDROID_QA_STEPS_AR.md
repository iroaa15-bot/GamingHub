# خطة Android العملية — Gaming Hub v7.7

## على الكمبيوتر (Godot 4.5.1)
1. افتح `project.godot` من النسخة الجديدة وانتظر استيراد الصور.
2. شغّل `tests/godot_smoke.gd` من الطرفية: `godot --headless --path . --editor --import --quit` ثم `godot --headless --path . --script res://tests/godot_smoke.gd`.
3. شغّل اللعبة الرئيسية، وافتح «خمن صورتك» وجرّب اللغتين والعناصر على شاشة 420×840.
4. افتح Project → Install Android Build Template عند الحاجة، وثبّت Android SDK / Java المتوافقين مع Godot.
5. غيّر package ID من `com.gaminghub.prototype` إلى معرّف فريد تمتلكه **قبل** إنشاء التطبيق في Play Console.
6. أنشئ مفتاح توقيع release واحتفظ بنسخة احتياطية آمنة **خارج المشروع**. لا ترفعه إلى GitHub أو ChatGPT.
7. صدّر Android App Bundle (AAB) موقّعًا للاختبار الداخلي، ثم ثبّته على هاتفين حقيقيين.

## الاختبارات المطلوبة
- فتح/إغلاق/إعادة فتح اللعبة 10 مرات دون انهيار
- شاشة البداية، ملف الأطفال، اللعب الفردي، وواجهة اللغة العربية/الإنجليزية
- هاتف A ينشئ غرفة، هاتف B يدخل بكود، جولة أسئلة وتخمين، ثم إعادة اتصال
- الشبكة الضعيفة، انقطاع Wi-Fi، انتقال التطبيق للخلفية، وانتظار استيقاظ Render المجاني
- تسجيل FPS، وقت التحميل، والذاكرة على جهاز متوسط وضعيف
- التحقق من عدم عرض صورة اللاعب السرية له قبل انتهاء الجولة
- عدم عرض أي إعلانات أو مكافآت إعلانية مزيفة؛ AdMob الفعلي غير مدمج بعد

## القياس
بعد كل اختبار ناجح موثّق، غيّر البند المناسب إلى `true` في `release/manual_qa.json` ثم شغّل:
`python release/release_gate.py --strict`

`--strict` يفشل عمدًا طالما توجد متطلبات ناقصة. النجاح في Python لا يعادل نجاح اختبارات Android.
