# إصلاح انهيار دخول الغرفة — سبب مثبت وإصلاح محدود

الفرع integration/gaminghub-final-20261024، الأساس 395bb3d0fb1dc6882cd871a61dd313b5f3c442b8. العمل السابق وAPK الأصلي محفوظان. لا عمل واجهة أو ميزات جديدة ضمن هذا الإصلاح.

## السبب والدليل

هاتف OPPO CPH2015، Android 9، والـAPK المسحوب من الهاتف يطابق بصمة APK المسلم: 250c348f660dc51ff6ed48341d5cd69b9dd56aca990db54a8a672e14b21345b2.

السجل الأصلي أظهر SIGSEGV على GLThread أثناء دخول الغرفة. اختبار الانتقال دون أي لمس أو صوت نقرة أعاد الانهيار؛ الانتقال من Main إلى مشهد فارغ بقي 15 ثانية. إنشاء جسر الصوت منفردًا دون مستمع خطأ بقي حيًا لكن أعلن عدم توفره.

اختبار الهاتف المباشر أثبت: Engine.has_singleton("GamingHubVoice")=true، وplugin.has_method("getVoiceApiVersion")=false، بينما plugin.call("getVoiceApiVersion") يرجع 2. إذن الإضافة مطابقة للواجهة، لكن فحص has_method غير صالح لحد JNI هذا. الجسر الأصلي يصدر voice_unavailable خطأً. مستمع الخطأ في الغرفة يعيد set_consent(false)، والذي يعيد الفحص نفسه؛ وفي Photo Duel يضاف تحديث الواجهة لنفس الحلقة. أُثبت التداخل المتزامن بعمق 1 ثم 2 ثم 3 دون رجوع، مع حد تشخيصي منع تدمير التطبيق. تلك الحلقة تستهلك المكدس؛ ليست مشكلة WSS أو الاهتزاز أو Tween.

مرجع Godot الأصلي لنفس قيد JNI: https://github.com/godotengine/godot/issues/106436 . الاستنتاج قائم على سجل هذا الهاتف، لا على تشابه تقرير خارجي فقط.

## التغيير

- android_voice_integration_bridge.gd: محول وراثة محدود يستدعي getVoiceApiVersion مباشرةً على Android ويتحقق من 2، ثم يربط الإشارات الأصلية. بقية الميكروفون والتوجيه والموافقة والإيقاف ودورة الحياة موروثة دون إعادة تنفيذ. حماية من إعادة دخول عملية الربط أثناء إشعار الخطأ.
- multiplayer.gd وphoto_duel_voice_adapter.gd: استعمال المحول الجديد، وحارس لإعادة دخول معالج الفشل. لا تعطيل للصوت ولا تغيير لقواعد الغرف أو الواجهة.
- اختباران جديدان لحد الربط ومعالجة الفشل في الغرفتين. أدلة هذه الجولة في evidence.

android_voice_bridge.gd وAAR ومحرك الصوت الأصلي لم تُعدل. لا تغيير main.gd أو main branch أو السيرفرات أو الصور أو AdMob أو اليومي. project.godot غير المحفوظ من العمل السابق بقي كما هو وخارج الالتزام.

## النتائج الفعلية

| الاختبار | النتيجة |
|---|---|
| سبب JNI والحلقة المتداخلة على الهاتف | مثبت بالسجل |
| ربط API صحيح واختبار فشل Photo Duel | PASS محلي، قبل التوقف؛ لم يُعد |
| حارس فشل الغرفة الكلاسيكية | PASS محلي جديد |
| Main إلى غرفة Photo Duel بالإصلاح المؤقت ثم Main | انتقالان مسجلان على الهاتف ضمن diagnostic source overlay؛ ليس قبول APK الجديد |
| بقية الانتقالات وتكرار الضغط في APK النهائي | BLOCKED: الهاتف اختفى من ADB |
| إذن الميكروفون/onMainResume/الصوت دون سماعة | BLOCKED: لم يُنفذ اختبارها الكامل |
| WSS عبر الإنترنت | BLOCKED سابق، لا نشر؛ ليس سبب العطل |

تحذيرات تسرب RID عند إغلاق محرر Godot محفوظة كاملة كما في خط الأساس السابق، ولا تُحتسب اختبار Android أو إصلاح تسرب ذاكرة.

التشخيص شغّل ملفات مؤقتة داخل التطبيق المثبت دون install/uninstall أو clear-data أو تعديل APK. لم يُبن APK أثناء البحث. رمز native الدقيق لم يُنسب إلى رموز release غير المطابقة لبصمة debug؛ لم تُستخدم مطابقة رموز خاطئة كدليل.

بعد حفظ الالتزام: APK جديد باسم مستقل عند نجاح التصدير؛ قبول الهاتف النهائي يبقى BLOCKED إلى أن يتصل ويُختبر فعليًا. لا إعادة لاختبارات WSS الناجحة، ولا تثبيت اعتمادات أو نشر أو Actions.
